# Skills

本目录保存本项目自编、可共享的技能。每个技能独立放在一个子文件夹中，以 `SKILL.md` 为入口。
具体名单、用途、依赖及验证状态见 [技能目录](技能目录.md)。AI 使用与维护方法见 [agent.md](agent.md)。

## 结构

```text
skills/
├── README.md
├── agent.md
├── 技能目录.md
└── 技能名称/
    ├── SKILL.md
    ├── agents/          # 可选的客户端展示信息
    ├── scripts/         # 可选的执行工具
    ├── references/      # 按需读取的说明
    ├── assets/          # 输出模板等资源
    ├── examples/        # 可独立运行的非私有样例
    └── requirements.txt # 有程序依赖时提供
```

不要求每个技能都包含全部可选目录。使用规则集中在 `SKILL.md`，较长资料放在 `references/`。
只收录经过筛选的自编内容，不附带个人账号、私有文档清单或第三方技能副本。

## 安装与调用

支持技能的客户端可以按路径读取 `skills/技能名称/SKILL.md`。
需要项目自动发现时，把所选子文件夹复制到项目的 `.agents/skills/`；需要用户级发现时，复制到客户端配置的技能目录。
目标已有同名技能时先比较版本，保留已有内容，不直接覆盖。
此目录不会自动安装依赖或修改个人技能配置。

例如，将单个技能复制到项目发现目录后，在客户端调用 `$report-organizer`。
也可以不安装技能，直接按照该技能说明执行随附脚本。
Python程序、绘图库和中文字体等依赖由使用者显式准备；具体命令见对应技能的工具说明。

## 新增与维护

新技能使用小写字母、数字和连字符命名，一个文件夹只承载一个有明确用途的技能。
新增后更新技能目录的对应行，记录真实验证范围。不要在通用README或agent.md中维护第二份技能名单。
技能调用只授权本次指定任务；发布文件、推送仓库或修改外部服务仍按用户授权执行。

本目录提供工作流程和工具。技能存在、结构校验通过或样例运行成功，都不证明某个实验结果正确。
