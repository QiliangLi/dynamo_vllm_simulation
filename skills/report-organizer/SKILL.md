# 报告整理

默认使用中文。用本技能随附的固定工具和配色整理结果。先说明结论，再给数据、机制解释和限制。
使用本次实际输入和配置，不套用历史实验数字。只整理报告不隐含重新运行实验。

## 资源与入口

- 先读 [格式与图表规范](references/format.md)，再按 [固定工具说明](references/fixed-tools.md) 选择数据入口。
- 固定入口为本文件夹的 `scripts/generate_report.py`。仅重绘时间线时可用 `scripts/redraw_timeline.py`。
- 其他日志先转换为 [标准数据](references/report-schema.md)，不重写已有统计、积分、绘图和打包逻辑。
- [最小合成样例](examples/dataset.json)用于检查环境和输出格式，不是性能实验。
- [报告模板](assets/report-template.md)用于补充正文。图表样式位于 `scripts/plotting/report_style.py`。

## 执行

1. 确认数据目录、实验版本、工况、方案、重复次数、SLO期限规则与输出目录。已有上下文能确定时直接使用；关键项缺失时再问用户。
2. 先校验输入与来源。区分正式请求和预热、业务类别和在线轻重分类，以及单次轨迹与多次汇总。只有原实验设计支持时才做跨运行聚合。
3. 用固定工具生成新报告目录。工具支持现有报告、DV逐层日志、跨目录方案清单或标准dataset。它不安装仿真环境或运行实验。
4. 补充第0、6、7、8、10章分析，可通过 `--narrative` 提供JSON正文。数值排名不能替代原因分析；区分观察、推断和待验证机制。
5. 阅读 `report_data/validation.json`。它检查逐请求SLO、分位数、时间账本、可用带宽积分、来源和产物SHA、链接及ZIP。没有同口径原报告时明确仅完成内部一致性校验。
6. 打开本次全部PNG，检查中文、图例、颜色、坐标和留白。看图前保持 `data_validated_visual_pending`；实际看图后执行 `--finalize 输出目录 --visual-reviewed`。
7. 交付主报告和分享包链接，说明实际完成的验证与限制。包内包含重绘数据和脚本，不等于完整原始运行归档。

正文需要修订时修改narrative并生成新目录。不要直接修改受哈希保护的产物，再绕过校验。
默认沿用用户项目中的报告目录；尚无约定时选择清楚命名的新输出目录，不覆盖旧报告。

## 统计与图形边界

- 请求期限逐条匹配；TTFT为网关到达到首token，分位数用nearest-rank。客户端与网关计时分别说明。
- 时间线使用到达冻结或每层开始时的动态轻重标记。历史A/B/C/D仅用于明确标注的业务分组。
- 红色为在途IO并集减去名义计算，不等于纯读取依赖阻塞；灰色包含空闲、排队和控制，不能从颜色补造原因。
- 名义模型计算占比不是硬件实测利用率。带宽按事件重叠积分，不能对不等长事件直接取平均或凭总字节摊平。
- 缺少数据时注明原因，不伪造图表。原生日志带宽适配仅覆盖文档说明的单盘、零启动延迟、grouped max-min模型；其他模型提供真实区间或使用标准dataset。
- 当前工具不自动做多种子统计聚合。单次结果不能写成稳定收益或统计显著。
- 本技能不包含私人报告、账号或发布权限。推送Git、上传文档及外发报告按用户本次授权执行。
