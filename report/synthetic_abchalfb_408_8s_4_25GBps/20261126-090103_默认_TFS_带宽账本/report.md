## 0. 总判决

- 相比默认全轻读，新 TFS 的整批完成时间变化 -2.9%，平均 TTFT 变化 -15.7%，四实例平均完成时刻变化 -2.1%。
- 相比普通 TFS，新 TFS 的整批完成时间变化 -3.3%，平均 TTFT 变化 +1.8%，四实例平均完成时刻变化 +1.8%。

## 6. 机制解释与前序对照

默认强制全轻读，实际 KV 读取保持一致。普通 TFS 冻结进入时的 P75 轻重标记，以重读条数计许可。新方案增加均摊门槛 6.25 GB/s，以原模型需求判重，再将画像带宽四舍五入到整数 B/s，用于 RPC、账本与本地选择。被拒后用剩余带宽和均摊门槛选轻读。

|策略|A 判重/总数|B 判重/总数|C 判重/总数|许可获批|拒绝次数|曾被拒绝或跳过的请求数|
|---|---:|---:|---:|---:|---:|---:|
|默认全轻读|0/120|0/144|0/144|0|0|0|
|普通 TFS|120/120|3/144|0/144|123|203|108|
|带宽账本 TFS|120/120|0/144|0/144|120|600|80|

新 TFS 的累计 KV 等待为 4.958 s，普通 TFS 为 4.661 s，默认策略为 6.770 s。首层等待取提交至存储完成；逐层等待取上一层计算完成至下一层读取完成的正差。跨 worker 求和，不能直接从整批完成时间扣除。时间线红色为在途读取减名义计算的区间，口径与依赖等待不同。

新方案账本峰值为 20.374 GB/s；自身需求大于 25 GB/s 且单独获批 0 次；最后账本归零。本次拒绝后选择轻读：符合上限 156 次，选择最小需求兜底 0 次。沿用上次拒绝上限：符合上限 0 次，兜底 0 次。以上为选队事件计数，同一请求可能多次被选。

普通 TFS 的额度更新次数按额度分布为 `{"null":1,"7":9,"2":398}`。普通 TFS 的申请 RPC 平均/P95 为 2.503/4.445 ms，新方案为 1.454/3.257 ms。拒绝次数包含重复申请。

## 7. 计算模型与结论限制

本次每种策略仅执行一次。独立路由和 CPU 调度时序有波动。模型计算占比和模拟分配带宽不等于真机 NPU 与 OD 测量；无法据此确认 AIV/HBM 竞争。轻读没有全局预算预留，过载仍可能出现。

带宽账本 TFS有一轮未计入报告。Dynamo Python 端严格字段校验拒绝新增带宽画像字段。客户端成功 0/408 条。该轮日志保留在本机 `408-bandwidth-failed-metadata`，报告使用最终版本的完整验收轮。

带宽账本 TFS有一轮未计入报告。小数带宽版本曾通过，随后统一按整数 B/s 最终版本重跑。客户端成功 408/408 条。该轮日志保留在本机 `408-bandwidth-superseded-float`，报告使用最终版本的完整验收轮。
