# C++ 独立盘存储后端

本次发布两项已验证的优化：Python grouped 后端缓存未变化的带宽分配；可选 C++ 后端执行进度更新、完成判断和逐盘带宽缓存。默认后端仍为 Python。

C++ 保持原有 HRW 放置、逐层加载、max-min 带宽语义、0.5 ms 轮询和服务锁。请求提交、完成或到达可读时刻后，仅重算受影响盘的带宽。未变化的盘复用分配结果。它不采用 SimGrid，不启用通知模式、单写者模式或按盘多进程。

## 使用

先按主说明准备 Linux/WSL、Python 依赖和带加权记账的 Dynamo 扩展。还需 `g++`。在 `dynamo_vllm_cpu_sim/` 执行：

```bash
.venv/bin/python scripts/run_benchmark.py \
  --case mooncake_abc_360_4s_12_100GBps --arm direct \
  --disks 4 --disk-gbps 25 --storage-backend cpp \
  --dynamo-python /path/to/native-build/python \
  --output /path/to/new-smoke --smoke
```

正式运行移除 `--smoke`，使用新的输出目录。新 TFS EDF α=0.1 使用 `--arm tfs-a01`。原入口的其他策略选择不变；本次性能对照只覆盖直接 EDF 和新 TFS α=0.1。原 benchmark 输入、token 预算、到达时刻、SLO 和配额规则均不改变。

原生库首次使用时按源码和编译参数哈希构建到用户缓存目录。正式窗口不包含编译时间。`storage.final.json` 记录原生源码 SHA、构建信息和逐盘带宽重算次数；冻结运行包包含 C++ 源码。不要提交生成的共享库。

## 支持边界

仅支持 Linux、独立磁盘（`shared_link_Bps=null`）、grouped max-min 和逐层 poll/locked。共享链路、SA 分配、bulk、逐块表示、通知模式和单写者模式不支持，配置不匹配会报错。固定 benchmark 默认共享池配置不变；运行 C++ 必须显式指定独立盘拓扑。

七图报告保留此前八次正式运行：两种策略、两种后端、各两轮。Python 对照已经包含带宽缓存。C++ 与逐盘缓存同时启用，不能把整体收益归因于单独一项，也不能解释为真实 SSD 性能提升。交付入口的新增验收另存，不替换报告数字。

## 同步边界

`RUNTIME_SYNC.json` 固定共享文件的交付 SHA。`source_exceptions` 同时记录研究版的 SHA 和差异理由：交付版保留原 poll/locked 路径，排除研究版通知与单写者实验；原生测试跳过非 Linux 主机。校验器仍分别验证两侧 SHA，任何未记录的变化均失败。这不是允许任意忽略源码差异。
