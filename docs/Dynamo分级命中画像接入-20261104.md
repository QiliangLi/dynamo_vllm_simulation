# Dynamo 内部的共享存储准入画像

开发分支：`codex/dynamo-tier-admission-20261104`。固定 Dynamo：`b83b1d9304ebfc624709ac46db32b1b6f1ff1615`。

## 约定与执行顺序

所有实例共用同一个存储，实例对等。一个请求只生成一个画像和一个重读标记。

```text
普通 HTTP 请求 → 网关只登记 ID、到达时间、输入长度
  → Dynamo 原生分级 KV 查询
  → 读取共享存储命中量 → 一次画像、P75 分类和历史登记
  → scorer 读取同一个重读标记 → 原生 picker → 完整资源 booking
  → 下发已有 storage_hint / EDF 元数据
  → vLLM Scheduler 按原规则申请额度 → Connector 查询实际命中
  → 原生 allocate_slots → 原有逐层读算 → 首 token 释放额度
```

没有按候选实例生成画像，没有预分类历史，也没有选择后的 commit 回调。
分类继续使用原有 `on_arrivals`，历史和 `threshold_version` 每请求只更新一次。
重复的相同画像回调保持幂等，不再增加历史。相同请求改变冻结画像仍不支持。

scorer 对所有候选读取同一请求重读标记。既有 α 增量计分、等待重读折扣和获准补齐保持原规则。
picker、容量检查、完整资源 booking、Scheduler token 预算和块分配不因画像搬移而改变。
本模式下分类在 scorer 之前可用；α=1 时当前请求增量不打折。

## 数据来源与边界

画像入口由 Dynamo 内部在原生分级查询完成后调用。没有使用客户端提供的命中、估时或类别。
Python 估时、原有分类算法和中央额度账本继续复用现有服务；未重新实现一套 Rust 策略。
内部画像回调每请求一次，使用带身份校验的本机 HTTP，5 秒超时。
worker 的额度查询继续使用既有配置的 Dynamo Runtime/TCP/Unix RPC。
画像返回的元数据直接随请求传递；下发前没有第二次画像 RPC。

本共享模型使用 `OverlapSignals.tier_overlap_blocks.disk` 的原始块数。
固定上游在该字段合并 Disk 和 External 延伸量；不能称为纯本地磁盘命中。
相同共享前缀可能由多个实例上报，因此取其最大前缀长度一次，不将副本命中量相加。
该操作不按实例建立画像或更改原生路由的 overlap 数据。
`estimated_remote_tokens = min(disk_blocks, floor((prompt_tokens - 1) / block_size)) × block_size`。
最后一个 prompt token 仍由 vLLM 计算。计算估时、读取字节、P75 压力和期限沿用原公式。

适用条件是本实验的共享存储、对等实例及关闭实例本地前缀缓存。
不新增 GPU/HostPinned 差异画像，不建模异构实例，也不新增真实存储事件或 KV 数据传输实现。
分级索引仍依赖存储缓存事件。没有事件时，只能得到零或不完整命中。

索引命中不代表 KV 已加载。Connector 仍负责实际查询、逐层读取和层屏障。
允许预计读取量与实际读取量有偏差，只记录 `tier_lookup_mismatch`；
不因偏差而报错、退额、修改画像或自动重分类。实际 KV 分配和执行使用实际命中。
例如预计轻读而实际重读，仍按原画像准入，暂不补申请额度。

## 启用与小测

必须重新构建独立扩展，不能复用旧的多候选协议构建。原始上游和已安装 wheel 不变。

```bash
python scripts/build_weighted_dynamo.py --source /path/to/pinned/dynamo \
  --output /new/build --tier-admission --jobs 4
PYTHONHASHSEED=0 python -m unittest discover -s tests -p test_dynamo_tier_profile.py -v
PYTHONHASHSEED=0 python scripts/validate_dynamo_tier_admission.py \
  --routing-python-path /new/build/python --output /new/smoke
```

新配置设置 `admission.profile_source=dynamo_tier`、`router_mode=kv` 和既有
`scheduler/arrival/tfs/first_token/aging_enabled=false` 条件。
不接受 `cache_model=first_seen` 的逐请求命中绑定；默认 trace 模式及固定 benchmark 不变。
零 overlap 评分权重时，新模式仍启用事件索引，不把缓存信息源与评分权重绑定。

两实例八请求小测通过 STORAGE 测试事件维护真实 Dynamo 索引，模型/KV 读取为 CPU 仿真。
验收每请求恰好一次画像和分类、首次 scorer 前分类、所有候选使用相同标记、完整资源回收。
增加 `--factor 1` 可核对当前增量不打折；`--event-hit-fraction 0.5` 可核对允许命中偏差。
`[ROUTING] Best` 是 native 调度返回后的宿主日志，不能当成 picker 的实际调用时点。
