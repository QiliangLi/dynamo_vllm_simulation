① Dynamo：加性 logit 代价打分

怎么读这张图：最上一行是主路径——请求经 Envoy（只转发）进入 ext-proc 决策处理器（内嵌真实 Rust 选择核心），被转发到某个 vLLM worker；生成的 token 沿顶部弧线原路返回，网关在回程上顺手更新记账。中间的默认打分器是决策核心：对每个候选 worker 算一个代价 logit，谁小选谁。下面一排是打分器的三类输入：左＝网关自己记的账（零滞后）、中＝KV 事件索引（本仿真关闭，虚线）、右＝请求自带字段。左下、右下两个虚线通道"存在于系统、但不参与打分"。

公式外交互（图中虚线）

  • etcd 服务发现：决定"有哪些 worker 可选"（候选集合），本身不产生分数。
  • FPM 每步事件 → Planner：worker 每个前向步发一条指标（含 waiting 队列长度、本批耗时），只喂自动扩缩容，不进路由公式——这就是"队列信息出得来、但路由听不到"的原因。
  • token 流回程：它是数据面本身；记账的四个更新（reserve / prefill_complete / add_output_block / free）全部"搭"在这条回程流上，没有独立上报通道。

② llm-d：过滤 ＋ 负载打分的插件链

怎么读这张图：路由器 ＝ Envoy（proxy）＋ EPP 决策插件。EPP 内部是一条三步链：先调 Render 服务把 prompt 精确切成 token 块（①）；再用常驻 KV 块索引把候选收窄到"缓存了这些块的 Ready pod"（②）；最后在候选里挑在途 token 负载最小的（③）。索引靠各 pod 主动播报的 KV 事件维护；在途 token 是 EPP 自己记的账——不是引擎内部队列。

三步与因子对照

步骤 / 记号是什么怎么得到
① token 块序列prompt 精确分词后的块哈希链（前缀须整段一致才算命中）调 vLLM /v1/*/render（含工具渲染），非本地估算

② 暖集饱和回退缓存暖集吞吐超过标定值时放弃亲和、回退低载 pod（缓存优先、负载兜底）部署时标定 peakPrefillThroughput
③ 在途 token 负载每 pod 已发入、未完成的 token 量；argmin 者胜出EPP 自记账：路由计入 prompt token、完成时释放（零滞后；因此该模式 EPP 单副本部署）

公式外交互（图中虚线）

  • discoverPods / Ready 门控：决定装哪些订阅器、哪些 pod 可进候选，不产生分数。
  • ROUTER 5559 重放缓冲：路由器重启后回放约 1 万条事件重建索引——恢复机制，不是因子。
  • 放置层（K8s scheduler 插件）另行工作，不在逐请求路径；llm-d 不抓引擎 Prometheus 指标进路由。

③ AIBrix：可换策略族，load-balance 为代表

怎么读这张图：路由器 ＝ Envoy Gateway（proxy）＋ ext_proc 路由插件，打分是一族可换策略。最典型的 load-balance：分子衡量"还有多少活"（running＋λ·queued），分母衡量"干得多快"（EWMA 吐出速率），再乘 KV 空闲惩罚。三个因子来自三个不同渠道：running / queued / kv_free 走 Prometheus 周期抓取（有滞后）；EWMA 吐出速率是网关自记账（零滞后）；prefix_match 默认来自网关自己的路由历史——是投影不是真相，要真相需打开 KV 事件同步（图中虚线）。

公式外交互（图中虚线）

  • Redis 跨网关副本共享前缀索引（AIBRIX_STATESYNC）；autoscaler 滑动窗指标聚合在控制面——都不在逐请求路径。
  • session-affinity / P/D 分离 / SLO 策略族：按请求另行选择，不改基础打分；slo-least-load-pulling 会现拉新鲜快照避免过期缓存。
  • 负载失衡前置门控：在所有策略之前统一收窄候选集合。
