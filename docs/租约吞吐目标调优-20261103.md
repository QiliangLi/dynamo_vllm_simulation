# 租约臂吞吐目标调优（完成时间↓ / TTFT↓ / NPU利用率↑）

| 项目 | 约定 |
|---|---|
| 日期 | 2026-11-02 ~ 2026-11-03 |
| 目标函数 | 完成窗口最短、mean TTFT 最短、等效 NPU 占用最高（=名义计算总量÷完成窗口÷12，与完成时间共线）。SLO 不在目标内，只作附带记录 |
| 对象 | tfs-lease 臂（`BENCH_LEASE_JSON` 注入配置），对照同版本三臂与 lease 默认参数（n1.2×m10） |
| 运行 | 全部在 WSL 统一入口，正式 72 预热+360 请求；T1~T8 共 25 组；基线复跑 a01×2、a1×1 |
| 噪声声明 | 同配置轮间 mean 差实测 ±15~30%、SLO ±3pp。小于该量级的差异一律表述为"打平"，不作优劣结论 |

## 1. 起点：为什么原 lease 在这三个指标上差

原 lease（n1.2×m10，期限保护全开）相对三臂：mean +20~98%、完成窗口 +30~47%、利用率 −5~14pp。三条机理（均有数据支撑）：

1. **期限否决是均值杀手**：条件(a)(b) 在 abc/abcd 各压后 1.7k~2.7k 次，被压后请求的等待全额计入 TTFT。
2. **判定线的均值最优位置随负载形态分化**：
   - 小需求密集（random，p50≈7.6GB/s）：线≈物理带宽（1.0~1.2×）时并发拉伸被抑制，mean 1147→961；线放到 2.5×（几乎不门控）反而 1336。
   - 巨需求（abc，p99≈123GB/s）：线 1.2× 时巨请求(>例外带135GB/s)被串行化（7787 次拒绝），mean 1921；线 2.0~2.5× 让巨请求并发读，mean 1317。
3. **重试退避的时间尺度要对准盘释放节奏**：abcd 重读大（例外路放行后约 20-30ms 释放）→ 15ms 退避把 mean 从 1374(T2) 压到 1162(T6)；random 重读小（约 6ms 释放）→ 15ms 退避反而超调（T7 1031 vs T4 961）。
4. **路由信号决定尾部**：m=10（f=0.1）把等待重读打九折计分，路由器不再摊开重读 → 尾部/完成窗口变差；a1（f=1）是三臂中完成窗口/利用率冠军即此理。T8（f=1）单轮完成 6847 接近 a1，但两轮跳动（7447），未形成稳定优势。

## 2. 代码支持（本轮新增，已入库存档）

- `lease.protect_inflight` / `lease.protect_urgent`（默认 true 保持期限保护；false = 吞吐模式跳过条件(a)/(b)）。见 `sim/stack/lease_ledger.py`，单测 `tests/test_lease_ledger.py::test_throughput_mode_skips_condition_ab`。
- `BENCH_LEASE_JSON` 支持 `retry_interval_wall_s` 注入 admission，及 `release_on` 覆盖（消融用）。
- 主臂断言不放松：`lease_events` 模式仍强制 first_token 释放=0。

## 5. 结论：目标冲突确认，分解为分场景策略

三个目标在**同一配置**下确实冲突（低线利于 random 均值、高线利于 abc 均值、f=1 利于尾部但伤均值），因此按负载形态分两套推荐 + 一处保留：

| 负载形态 | 推荐策略 | 相对当前最优的证据 |
|---|---|---|
| **小需求密集型**（random 类；逐请求高命中、需求 p50≪盘带宽） | **T4**：`n1.2/e1.5 + 保护关 + m10`（默认 retry 2ms） | 两轮均值对 a01 两轮：mean 973 vs 995、p95 2701 vs 2847、SLO 31.0 vs 28.8、util 45.7 vs 44.1 全部占优，完成 7614 vs 7578 打平——**五指标不劣且方向性全面占优**，另比 lease 默认 mean -15%、完成 -12% |
| **混合巨/中需求型**（abcd 类；含重读重计算） | **T6**：`n2.0/e2.5 + 保护关 + retry15ms + m10` | mean 1199 vs a1 1222 打平、vs a01 1296 **-7.5%**；SLO 32.8 vs a1 25.3 **+7.5pp**（白送）；完成 7158 vs a1 6780 落后 ~5%（未突破）——若考核均值/SLO 选 T6，若考核完成时间/利用率仍选 a1 |
| **纯巨需求轻算型**（abc 类） | **保留 a01** | 最优 lease（T2）mean 1317 vs a01 均值 1156 仍 +14%（超噪声），不换；若尾部敏感可选 T2（p95 3287 vs 3565/3678 占优，其余打平） |

**通用规律（供后续负载定标）**：判定线取"该负载重读需求分布的分位数≈盘带宽"的位置——小需求负载取 ~1.0-1.2×，巨需求负载取 ~2.0-2.5×；重试退避 ≈ 该负载重读的典型释放时长（random≈6ms→默认，abcd≈25ms→15ms）；期限保护在纯吞吐目标下应关闭。

**未突破项（诚实记录）**：abcd 的完成时间/利用率冠军仍是 a1（6607-6953 / 46.2%）；T8（f=1 路由）单轮接近但两轮不稳，残余差距 ~5% 归因于 lease 每重读 4 条同步控制消息占用调度线程（223 重读 × ~3ms）与门控等待的尾部残留。下一步若要突破，方向是把 ReadGate 申请异步化（不阻塞调度循环）。

## 6. 复现

```bash
cd dynamo_vllm_cpu_sim
BENCH_LEASE_JSON='{"compute_slots":10,"loading_slots_per_worker":1000000,"protect_inflight":false,"protect_urgent":false,"line_factor_normal":1.2,"line_factor_exception":1.5}' \
.venv/bin/python scripts/run_benchmark.py --case mooncake_random_360_4s_12_90GBps \
  --arm tfs-lease --dynamo-python build/weighted-dynamo-8/python \
  --output results/benchmark_runs/<新目录>          # T4

BENCH_LEASE_JSON='{"compute_slots":10,"loading_slots_per_worker":1000000,"protect_inflight":false,"protect_urgent":false,"retry_interval_wall_s":0.015,"line_factor_normal":2.0,"line_factor_exception":2.5}' \
.venv/bin/python scripts/run_benchmark.py --case mooncake_abcd_360_4s_12_90GBps \
  --arm tfs-lease --dynamo-python build/weighted-dynamo-8/python \
  --output results/benchmark_runs/<新目录>          # T6
```

100GB/s 变体负载预期同规律（线随带宽等比缩放）；AgentX/人工ABC 为合同三臂负载，不适用。
