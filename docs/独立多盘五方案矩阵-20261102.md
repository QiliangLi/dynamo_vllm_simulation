# 独立多盘五方案矩阵

本入口将六份冻结负载分别运行五种策略。每次正式运行启动12个逻辑实例，先排空72条预热，再发送360条正式请求。运行顺序使用固定种子20261102打乱；每种组合保留一次有效运行，不把重试视为重复实验。

## 负载与磁盘

|负载|计划到达窗口|独立磁盘|
|---|---:|---:|
|agentx_random_360_12s_12_180GBps|12 s|6 × 30 GB/s|
|mooncake_abc_360_4s_12_100GBps|4 s|4 × 25 GB/s|
|mooncake_abcd_360_4s_12_100GBps|4 s|4 × 25 GB/s|
|mooncake_abc_360_4s_12_90GBps|4 s|3 × 30 GB/s|
|mooncake_abcd_360_4s_12_90GBps|4 s|3 × 30 GB/s|
|synthetic_abc_360_6s_12_90GBps|6 s|3 × 30 GB/s|

GB使用十进制。每盘独立限速，`shared_link_Bps=null`，盘间不能借用带宽。KV块使用已有HRW内容哈希放置，盘内使用grouped max-min分配。基准目录的输入、命中、到达时刻、计算模型及原始共享池配置保持原值；分盘参数显式保存在实验冻结包。

Mooncake保留`glm5_actual_batch_work_v2`；AgentX和人工ABC保留各自的`direct_sum`。不同负载之间不是只改变输入的受控模型对比。AgentX仍显式允许300481的公式上下文上限；这不是实机长上下文定标。

## 五种策略

|参数|准入位置|实例内排序|等待重请求计分|
|---|---|---|---|
|direct-fcfs|直接准入|原生FCFS|关闭折扣|
|direct|直接准入|原生EDF|关闭折扣|
|old-tfs|网关TFS，保留动态分类|原生EDF|关闭折扣|
|tfs-a01|Scheduler分配前TFS|原生EDF|α=0.1，获准补齐|
|tfs-a1|Scheduler分配前TFS|原生EDF|α=1，获准补齐|

四类执行反馈和空闲强制准入均关闭，额度在首token释放。TFS继续读取总参考带宽并执行全局标量配额。分盘影响实际读取完成时间；本入口没有增加逐盘压力感知的准入或路由。

每步最多4条序列、8192新增token，block=16，78层，时间缩放K=1。使用冻结vLLM、Dynamo、Ascend源码及原生Dynamo RPC v2。宿主为CPU壁钟仿真，公式计算占比不代表真实GPU利用率。

## 运行

在Linux环境激活已按主README准备的运行环境。设置`DYNAMO_PYTHON`为已验收的原生扩展目录；输出目录必须为新目录。

```bash
python dynamo_vllm_cpu_sim/scripts/run_disk_matrix.py \
  --output /absolute/new/disk-matrix \
  --dynamo-python "$DYNAMO_PYTHON"
```

先执行六次冒烟，再执行30次正式运行。`plan.json`保存顺序和拓扑；`attempts.json`保留所有尝试；`progress.json`保存验收数量。只有已清理且没有保护失败的已知启动/网络故障才自动重试。断点恢复使用相同命令加`--resume`；不得更换冻结输入或运行源码后继续混合计数。

单个基准也支持显式覆盖：

```bash
python dynamo_vllm_cpu_sim/scripts/run_benchmark.py \
  --case mooncake_abc_360_4s_12_100GBps --arm all-five \
  --disks 4 --disk-gbps 25 --output /absolute/new/one-case \
  --dynamo-python "$DYNAMO_PYTHON"
```

`--arm all`仍只选择原有的direct、tfs-a01、tfs-a1三种策略。拓扑覆盖必须保持原总参考带宽不变。

## 验收与报告

验收包括有效配置逐项比较、预热排空、正式请求ID集合、独立计算公式、逐层屏障、KV读取、原生队列类型、EDF排序、原生路由最小分选择、许可及路由账本归零、RPC流排空和进程退出。

短冒烟可能在两个1秒指标采样之间结束。原生selector日志中明确的正`raw_prefill_blocks`可作为已预留负载的交叉证据；原生候选比较及最终零账本仍必须通过。此验收兼容不改变指标采样频率或运行策略。

完成后使用固定适配器和报告工具：

```bash
python scripts/report_tools/build_disk_dataset.py \
  --matrix /absolute/disk-matrix --case BENCHMARK_ID --output /absolute/new/dataset
python scripts/report_tools/generate_report.py \
  --dataset /absolute/dataset/dataset.json --output /absolute/new/report
```

适配器按记录的逐层提交时刻重放冻结的独立磁盘模型，核对每次读取完成时刻和逐盘字节积分。逐盘带宽图按10 ms积分分桶。离线重放不是重新运行一次性能实验，也不把所有磁盘画成始终满载。

逐张检查图片后执行`--finalize 报告目录 --visual-reviewed`。公开归档保留标准派生数据、配置、SHA256和复现工具；大型原始运行事件留在本机。矩阵报告按对应benchmark存入`report/`，总览放在同一研究的一份报告目录内。

公开归档的标准dataset省去重复的逐事件盘速率数组，保留总带宽事件和逐盘10 ms积分表；与源汇总及实例账本核对一致。AgentX公开数据重绘的8张PNG与源图逐字节相同。report目录按原字节保存，避免Windows换行转换破坏manifest中的SHA256。
