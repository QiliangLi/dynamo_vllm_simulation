## 1. 四项技术与现状差距

| # | 技术 | 方案要求 | 本仓库现状（实现事实） | 差距 |
|---|---|---|---|---|
| 1 | 轻重判定 | 轻重线 L=单盘带宽×10%，与负载无关，只决定协议路径 | P75 分位阈值在线更新（`sim/admission.py:84-94`），预热后重置；依赖负载统计 | 分类口径需新增带宽派生线 |
| 2 | 双信号路由 | 重读按 A(i)+B(i)·S̄/m(i) 选实例；等带宽只进 B | Rust scorer 只有一个 α 折扣信号（`patched/weighted_routing/pending_score.rs:187-198`）；获准即补齐计分 | 需改 overlay 公式与激活时机 |
| 3 | 每盘放行 | 每盘带宽账本（B/s），五步放行 + 两护栏 | 许可按条数计数：cap=参考带宽÷P75阈值（`sim/admission.py:88`）；账目无带宽单位、无盘维度 | 需新增每盘 B/s 账本与放行规则 |
| 4 | 事件驱动记账 | 读开始加账、末层读毕减账；TTL 兜底、周期对账 | 释放挂 HTTP 首 token（`sim/stack/admission_service.py:468`）；执行事实只进离线日志（`sim/stack/load_observation.py`）；无 TTL、无对账 | 需恢复两条在线事件并建 TTL/对账 |

现有链路与方案有一处已天然一致：网关转发时不占额度（重读信息下发 V1 §1），
对应方案"路由器立即转发、压后=留在实例等待队列、没有调度器排队"。
vLLM 侧被拒请求 prepend 回 `step_skipped_waiting`（`sim/stack/scheduler_admission.py:184-189`），
即方案"拒、留队"语义。

## 4. 模块一：轻重判定（hint v2）

**设计决定**：分类改为带宽派生线，与负载统计解耦。

- 判定：`max_d(d × 盘d块占比) > L` ⇔ 重读。单盘负载即 `d > L`。
- d 沿用画像 `pressure_Bps`，不新造公式。与方案"总读量÷独占完成时间"的差别是
  分母不含独占读时（90 GB/s 下 1.5 GB 读约 17ms，相对计算时长是小量）。
  此差别是待验证假设，定标步骤核对。
- 分类在到达时冻结进 hint，版本升为 2：

```json
{
  "storage_hint": {
    "version": 2,
    "is_heavy_read": true,
    "demand_Bps": 21000000000,
    "per_disk_shares": [{"disk": 0, "share": 1.0}],
    "estimated_remote_read_bytes": 1500000000,
    "deadline_s": 4.0,
    "line_version": 1
  }
}
```

- 传输复用 `nvext.annotations` 通道（`sim/stack/storage_hint.py:39-48`），
  worker 恢复与一致性校验照旧；缺 hint 或伪造即报错，不默认轻读。
- P75 代码路径保留给 direct 臂，不删除。预热隔离逻辑对本臂无操作对象，照常运行。
- 标签只决定协议路径：重读走 acquire/租约/两事件；轻读零读直接读、只进周期聚合。
  标签不参与排序（EDF 共用）。与方案"角色边界"一致。

**部署检查**（运行时可测，写入 lease 检查文件）：

- 检查一：超线占比 f 与消息率 = 到达率×f×4。
- 检查二：L ≤ 容差带 ÷（到达率 × 对账周期）。

**步骤 0 定标（先于任何实现运行）**：`run_benchmark.py` 的 `prepare()` 已生成
profiles.json（含 T0 与画像）。离线统计各负载 d 分布与超线占比 f，填表：

| 负载 | P50(d) | P95(d) | f=超线占比 | 预计消息率 |
|---|---|---|---|---|
| mooncake_random_360_4s_12_90GBps | 待填 | 待填 | 待填 | 待填 |
| mooncake_abc_360_4s_12_90GBps | 待填 | 待填 | 待填 | 待填 |
| mooncake_abc_360_4s_12_90GBpsd | 待填 | 待填 | 待填 | 待填 |

若 f 接近 0，本臂在该负载退化为 direct 口径，需先向用户报告再决定是否运行。

## 5. 模块二：双信号路由

**设计决定**：不改 scorer 的资源口径，把双信号公式折算成现有块单位折扣。

数学等价：方案公式 `A + B×S̄/m`，其中 A 不含等待重读。现有 scorer 的
logit = 完整预测负载 − 折扣 = 活动负载 + 等待重读×f。
取 `f = 1/m` 时 logit = 活动负载 + 等待重读/m，与 `A + B×S̄/m` 同构
（等待重读 token 总量 = B×平均长度，按 m 摊入）。因此：

1. `waiting_factor = 1/compute_slots`（默认 0.25），折扣公式与机制不变
   （`pending_score.rs:187-198`）。tfs 两臂的 α 语义不受影响。
2. 硬反压：overlay 新增钳位。某 worker 等带宽重读条数 B(w) >
   `2 × lease.loading_slots_per_worker` 时该 worker 分数置饱和，不再接新重读。
   新 env `DYN_LEASE_LOADING_SLOTS`，由 runner 注入 frontend。
3. **激活时机后移**：现状获准即 activate 补齐计分（`admission_service.py:127`）。
   本臂改为 `lease_started`（读开始事件）到达后才 activate。等待折扣从获准持续到真正开读，
   对应方案三状态表"等带宽不算现在、在读才算"。
4. 轻读/零读从不进等待账本（登记仅限重读，`admission_service.py:446-450` 不变），
   天然只按 A 选实例。
5. 协议版本升为 `waiting-score-v2`，identity 文件同步。修改 overlay 后必须重新
   release 构建，三臂与新臂共用同一 binary（沿用现有 build receipt 校验）。

S̄ 不进 scorer（等待账本已持逐请求 token 数，比平均值更准）。
S̄ 只用于账房侧 Δ 与条件 (b)。

## 6. 模块三：每盘带宽账本与五步放行

**账本**（账房持有，每盘一本，B/s 单位）：

```text
ledger[d] = Σ 在读重读份额（读开始事件加、末层读毕事件减、TTL/对账回收）
          + 轻读聚合（周期从存储侧拉取估计）
```

- 等带宽未决不进加法，只在条件 (b) 用（方案 §8 作废记录②）。
- 轻读聚合来源：`op_stats`（`sim/stack/storage_service.py:218-238`）的
  `read_history` / `layer_read_history` 按 UUID 区分轻/重，窗口内轻读字节÷窗口。
  账房新增 `--storage-socket` 接线，runner 传递。
- 份额表随 hint v2 由网关预算（同一 HRW 哈希），账房校验后使用。

**放行规则**（对候选重读 c，盘 d，份额 s_c；ReadGate 现有申请时机即"加载位前一位"
的预取语义，往返与队尾等待重叠，不改）：

1. `ledger[d] + s_c ≤ 判定线` → 放行（正常路）。
2. 新总额 Σ′ > 例外带 → 拒、留队。
3. 拉伸预测：**复用 `weighted_waterfill` 同一函数**对（在读集合 ∪ {c}）重放分配，
   得每条在读的预测读毕时刻。不用解析式 k=Σ′/容量 做判定，k 仅作记录指标。
   理由：记账口径必须与真实分配同构（方案 E26f 教训）；当前分配按块数加权注水，
   与按需求比例分配在超订时结果不同。
4. 条件 (a)：每条在读 i 需满足 `预测读毕_i + 剩余算_i ≤ 期限_i`，任一超则拒。
   - 预测读毕_i 来自第 3 步重放。
   - 剩余算_i = `service_s_i × 剩余读比例_i`（layer_pipeline 下读与算逐层同进，
     以读进度近似层进度）。近似误差是待验证假设，由 10% 判定线容差与对账吸收，
     离线用 fine_trace 逐层事件核对。
5. 条件 (b)：每条紧迫 j（已登记重读、无许可、未完成、`期限−现在−服务_j < Δ`）
   需满足"放行 c 后预计最早开读_j ≤ `期限_j − 服务_j`"。最早开读_j 取重放推导的
   账本回落时刻序列，任一 j 被推过线则拒。
6. 全过 → 放行（例外路），账记 Σ′。

**护栏（优先于一切）**：

- 盘账为 0 → 必放一条。
- `ledger[d] + s_c ≤ disk_Bps`（富余）→ 必放。正常路已覆盖此情形，护栏防实现回归。

**每实例加载位**：某 worker 在读重读数 ≥ `lease.loading_slots_per_worker` 时，
acquire 返回 `reason='worker_loading_full'`，ReadGate 走现有 full 跳过路径。
对应方案实例内规则 2。

**与现有 cap 的关系**：`bandwidth_line` 分类下不再计算条数 cap
（`sim/admission.py:88` 仅 P75 路径使用）。租约账本的带宽口径取代条数口径。

**数字走查测试向量**：把方案 §4 的 30 GB/s 三盘算例做成单元测试配置；
90 GB/s 单盘负载另做一组（判定线 99、例外带 135）。

## 7. 模块四：事件驱动记账协议

**消息**（重读每条 4 条：acquire 往返计 2、lease_started 计 1、lease_completed 计 1；
activate 中继复用现有评分 RPC，不计新增）：

1. 申请/准许：现有 `FeedbackClient.control('acquire')` 往返，准许响应新增
   `ttl_s`（预计读毕 + `lease.ttl_margin_s`）与 `line_version`。
2. `lease_started`（读开始）：触发点为逐层父 `load_submitted`
   （`sim/stack/layerwise.py:96`）与 bulk `submitted`（`sim/stack/connector_rpc.py:101`）。
   账本从此刻加。
3. `lease_completed`（末层读毕）：触发点为逐层末层 ready `completed`
   （`layerwise.py:125-128`）与 bulk `kv_received`→`completed`
   （`sim/stack/executor.py:239-252`）。账即刻减。不等计算完成、不等首 token。
4. 兜底：
   - TTL 到期未收读毕 → 账房回收并记 `lease_expired`。
   - 周期对账：每 `lease.reconcile_interval_s` 拉 `op_stats`，按盘比对账本值与
     实际速率/字节，偏差超 `lease.reconcile_tolerance` 时以存储侧实际值校正并记事件。
   - `request_finished` 保留幂等兜底释放；`rollback` / `resolved_no_remote`
     （无外部命中）路径照旧立即释放。

**实现挂钩**：`LoadObserver.emit`（`sim/stack/load_observation.py:19-21`）是
统一出口。lease 臂且 rid 持开放租约时，在该点同步发控制 RPC；
其余执行事实仍只进离线日志。`AdmissionState.receive` 对旧执行反馈 kind
继续 raise（`admission_service.py:91-92`），仅放开两个新 kind；
`release_on='lease_events'` 仅 lease 臂通过校验，其余臂仍强制 first_token
（`admission_service.py:31-32` 的检查放宽为按臂判断）。

**释放语义变化**：lease 模式下 `first_token` 事件不再释放租约
（`sim/admission.py:197-205` 分支按 release_on 区分）。这正是与三臂的关键差异：
记账窗口从"下发到首 token"缩到"读开始到末层读毕"。
误差单侧性沿用方案论证：加账精确（账房本地时刻），减账偏保守（事件到达延迟），
浪费上界 = 释放延迟×释放速率，由 10% 容差再兜一层。

**失败语义**：与现有控制 RPC 一致。结果不确定即关闭连接、停止本轮准入，
不猜测、不自动重放、不伪造释放。时钟域沿用 `receiver_observation` 规则
（当前单机同域，发送方原值仅诊断保留）。

**S̄ 与 Δ 在线统计**：账房维护重读 `service_s` 的 EMA（S̄）与 P95（Δ）。
冷启动用画像 `reference_service_s` 初值，随完成事件收敛。初值敏感度是待验证假设。

## 12. 边界、风险与不做的事

- 定标未做（步骤 0 前置）：d 分布未知，f 可能接近 0 或 1；先离线核算，再决定运行范围。
- 性能未验证：方案 §10 未验证清单全部继承；本文任何数值不构成收益承诺。
- 消息路径为本机回环真实壁钟 RPC，不代表跨机部署；跨机时钟域规则仅保留接口。
- 当前负载单盘（D=1）；每盘账本结构按多盘实现，多盘行为仅单元测试覆盖，
  不改 benchmark 合同（单共享池带宽仍从 config/manifest 读取）。
- 剩余算近似（读进度代层进度）的漂移由容差与对账吸收，离线核对，不宣称精确。
- 不做：实时读取真实存储带宽的传感器、抢占/取消、PD 拆分、多模型、多前端、
  服务重启恢复、账房多副本。带宽与速率仍是仿真量，不得表述为实测。
- 三臂回归若失败即停止，不得为通过回归修改三臂语义。
