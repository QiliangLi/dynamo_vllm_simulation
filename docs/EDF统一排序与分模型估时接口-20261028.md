# EDF 统一排序与分模型估时接口

2026-10-28。用户要求：priority 统一使用 EDF，ABC 与 Mooncake 分别实现计算时间接口。

## 行为与范围

- `policy=priority` 统一对应 `request_ordering=edf`，按已冻结的绝对 `deadline_s` 升序。截止时间以模型时钟原点为基准，转换为整数纳秒作为原生 vLLM priority；同键沿用原生到达时间与请求 ID 比较。priority 不减 now/T0，不更新期限，不主动拒绝过期请求，不另行抢占正在执行的 batch。
- `policy=fcfs` 保留 FCFS。旧 `budget_priority` 配置名称作为带警告的 EDF 别名，规范化后的运行配置写 edf；当前实现不保留旧 slack 行为。旧冻结实验包不改，不能用新审计器重释旧日志。
- deadline 仍为 arrival+slo_multiplier*T0。SLO 倍率可配置，保持原默认4；它不是 EDF 算法常数。所有对照组使用同一套新参考时间及期限。
- 不改变 Dynamo 路由、TFS 配额、KV 字节、计算公式、批大小/硬件参数或固定依赖。新排序元数据、事件和审计使用 edf_priority 名称；旧 Python 模块/审计入口只保留转发兼容。

## 估时接口

`ComputeTimeModel.estimate_step(shapes, decode_tokens)` 接收本步实际 `(h,u)`，输出现有 timing 字典。`get_compute_time_model(compute)` 选择实现：

|实现|计算语义|
|---|---|
|SAComputeTimeModel|ABC / sa_e26f。真实 token/attention 配对求和，批级 eta 与单次启动；8层来自 profile，不按最长序列 padding|
|GLM5ComputeTimeModel|Mooncake / glm5_d950pr。复用冻结 GLM 算子、异构 batch 的最大长度上界和原参考 DP/EP；保留 dense/MoE 各层时长|
|LinearComputeTimeModel|原线性模式，保留一次 step 开销与 decode 计时|

保留 `estimate_step`、`reference_compute_s` 外部函数作为稳定入口。新模型必须实现相同结果契约；本次不把 ABC 切到 GLM，也不修改两种数学公式。

`get_reference_time_estimator(config)` 选择参考时间实现。其 `estimate(prompt_tokens,cached_tokens)` 返回纯计算秒数、参考读取秒数、参考服务秒数、字节与压力。SA 与 GLM 使用独立实现，计算调用各自 ComputeTimeModel，再由执行协议组合参考服务时间。请求画像只消费该接口。

- 每个参考 chunk 独立估算，h 随已计算 token 增长。读取的是最初外部前缀；逐层执行器首个 chunk 后 KV 已驻留，后续 chunk 不重复读取该前缀。
- bulk：参考读取+全部 chunk 计算。
- layer_serial：首个 chunk 各层读取/计算串行，后续 chunk 只计算。
- layer_pipeline：首个 chunk 用 `x1+sum(max(x_l,c_(l-1)))+c_L`，后续 chunk 只计算。各层计算直接使用执行器相同的层时长拆分。首次/逐层读取启动成本按配置计入；零读请求不创建读取时间。
- SA 参考读取使用 min(B_ref,q_max)，与原 SA singleton 标尺一致。GLM 使用配置的参考带宽和每层字节，不引入当前拥塞真值；多盘标尺仍为显式配置的参考带宽估计，不声称知道每条真实路径的剩余容量。
- request_profile 的模式号升级为 reference_v2。旧 v1 名称仅迁移为对应 v2 并警告，保存的有效配置明确写 v2。修正 GLM pipeline 的 T0 后，deadline/SLO 绝对值会变化；旧报告保留，不能把变化全归因于 EDF。
