# TFS前置分诊与反馈开销对照

本文说明可复跑配置和实现边界。性能结论以本次独立对照和`VALIDATION.md`为准。
默认配置不切换。

## 前置分诊配置

在完整的已有配置上合并下列字段。不要用此片段替代模型、存储和实例配置。

```json
{
  "policy": "priority",
  "request_ordering": "edf",
  "admission": {
    "mode": "tfs",
    "placement": "gateway",
    "classification": "arrival",
    "release_on": "first_token",
    "idle_bypass": false,
    "aging_enabled": false
  },
  "routing_accounting": {
    "enabled": false,
    "waiting_factor": 1.0
  },
  "experiment": {
    "batch_feedback": true,
    "coalesced_feedback": false
  }
}
```

`FrozenClassification`在请求到达时冻结重读标签。P75仍只使用已到达历史。
`AdmissionController.pick()`从统一待选队列选择可准入请求，按固定deadline排序。
未准入重读没有绑定到实例。轻读仍可通过。获准后由原生Dynamo选择实例。
原生booking、stream guard和实例选择器不变。vLLM保留token预算、slot分配和组批。

配额从中央准入持有到首token。前置方案仍可能把配额花在实例内排队上。
该方案没有实现“实际IO开始才扣配额”，也不读取其他实例的内部队列对象。
没有新增实时存储带宽传感器。

## 反馈模式

`experiment`是显式研究配置。两个字段必须使用JSON布尔值。

| batch_feedback | coalesced_feedback | 行为 |
|---|---|---|
| false或缺省 | false或缺省 | 保留原逐请求、逐层同步反馈 |
| true | false | 同一原生batch同一层合成一个同步帧；各请求事实独立入账 |
| true | true | 本地保存逐层事实，在下一同步生命周期/控制事件之前合并确认 |

合并模式保留事件ID、顺序、字节和原始发生时间。读取完成事件不能越过未确认的层事实。
缓冲上限为`max_num_seqs × layer_count`，原256KiB帧和RPC超时限制仍生效。
本次测试形状为最多4请求、78层。更大batch可能触发帧限制，不能静默丢弃或截断。
服务拒绝、超时和缓冲越界都使运行失败，不重连、不自动重放。

中央看到中间层事实会更晚。该模式不适合依赖实时逐层反馈进行决策的控制器。
当前P75请求数配额不消费中间层反馈，但反馈合并仍可能改变控制面排队。
不能根据减少RPC次数直接推断端到端更快。
后台线程异步发送只在外层研究脚本保留，没有合入此默认实现。

## 共用实现改动

- `read_admission.py`为活动许可维护请求索引。历史许可墓碑、幂等和释放边界保留。
- `trace_io.py`流式读取JSONL，并在有界缓存中复用不可变整数。每个数组仍是独立列表。
  输入记录、token值、顺序、浮点和布尔类型不变。缓存最多65536种整数表示。
- 审计文件使用64KiB缓冲。内存事件与控制生效时机不变，正常服务关闭时flush。
  被强制终止的失败运行可能缺少文件末尾，不能当作成功结果。

这些改动为同期对照共用，不能全算作前置TFS的策略收益。
GLM计算模型、共享盘容量、KV命中契约及上下游版本不变。
运行仍为CPU壁钟仿真，不是Ascend硬件延迟测量。
