# 等待重请求折扣计分与获准补齐

日期：2026-10-27。用于当前 CPU 多进程实验栈。

## 1. 配置

`routing_accounting.enabled` 缺省为 `false`。启用后，`waiting_factor` 缺省为 `0.1`，
允许有限数值0～1。它是等待heavy负载的计分比例。0表示等待不计分，1表示完整计分。
获准后始终完整计分。配置按启动生效，不支持运行中热更新。

```json
"routing_accounting": {
  "enabled": true,
  "waiting_factor": 0.1,
  "rpc_timeout_wall_s": 2.0,
  "python_path": "/absolute/build/output/python"
}
```

当前限单前端、单模型、aggregated workers、原生kv路由、block_size=1 或 16、无前缀缓存，
并使用scheduler侧冻结重读准入。启动器固定无路由KV重用、无overlap credit，
prefill-load-model使用默认none。不扩展多模型、PD分离和多前端复制。

## 2. 分数与资源

Dynamo仍在下发时创建完整scheduler booking，保留request guard、预测KV负载、
容量准入和清理。vLLM实际块分配仍由原分配器完成。新机制只修改默认scorer成本，
不打折资源数量，不在Python中替代worker picker。

```text
discount(w) = (1 - waiting_factor) × waiting_heavy_prompt_tokens(w) / block_size
weighted_prefill = max(0, raw_prefill - overlap_credit - discount)
weighted_decode  = max(0, raw_decode - discount)
score = prefill_load_scale × weighted_prefill + weighted_decode + 原active-request项
```

实验默认active-request项为0，prefill/decode等权；新请求自身的候选成本保留。
上述评分式使用 block 单位；等待账本使用 token 单位。资源gauge显示完整预测负载，Formula/WAITING_SCORE日志显示选择成本。不能混用两者。

## 3. 状态链

1. Gateway按冻结hint，将heavy的UUID和完整prompt长度登记到前端原生账本。
2. 原生SchedulerQueueActor选择实例并创建原booking后，绑定UUID、worker/rank、AttemptId，开始等待折扣。
3. ReadGate.acquire获准后，准入服务同步通知前端activate。确认后才返回成功，调度器继续KV查询和分配。
4. activate撤销等待折扣，分数补齐。native资源booking从始至终保持完整。
5. 实际无外部命中：回滚本轮permit，再发送routing_ready，使请求按普通计算完整计分。
6. 分配失败退额：对应permit的激活退回等待折扣。
7. 原生request-index删除booking时关闭评分记录。正常结束、取消、TTL和worker移除复用原删除路径。

同一permit重发幂等；已回滚permit不能重新激活。旧AttemptId的清理不能关闭新booking。
关闭记录保留墓碑，拒绝迟到激活。每个前端生命周期最多登记100000个heavy，达到上限明确报错。

## 4. 通信与失败

额度RPC继续使用原FeedbackClient，可选Dynamo TCP/MessagePack、TCP JSON或Unix。
前端评分账本另用仅本机回环的持久TCP JSON控制连接，不作为跨机器部署接口。
前端绑定随机端口，原子发布ready文件，包含协议、进程、epoch和比例。
客户端核对身份与比例，修改必须携带本轮epoch。

仅heavy登记、成功获准、回滚和无命中转换增加评分RPC；额度不足轮询不增加该RPC。
RPC耗时为壁钟，不除以K。真实栈增加了控制通信，不能直接沿用离线收益数字。

额度与评分账本不是分布式事务。通知超时或结果不明时，客户端关闭连接并停止本轮准入，
不返回成功、不换key自动重试、不伪造额度释放或请求结束。明确重复消息依靠身份幂等。
客户端断开后既有producer继续排空上游；无法确认执行终止时保留保守状态并中止验收。

## 5. 独立构建与运行

基础源码固定Dynamo b83b1d9304ebfc624709ac46db32b1b6f1ff1615，不升级上游。
patched/weighted_routing/apply_patch.py核对四个源文件SHA后，只在新目录应用Rust overlay。
原源码和已安装wheel均不覆盖。正常构建需要Rust1.96.1、C/C++、CMake、OpenSSL/Clang/ZMQ开发文件和protoc等。
Cargo从源码目录运行，以加载原.cargo/config.toml的tokio_unstable等设置。

```bash
python scripts/build_weighted_dynamo.py --source /path/to/pinned/dynamo --output /new/build/output

PYTHONHASHSEED=0 python scripts/run_tfs_stack.py \
  --config configs/sa_abc_stack.json --trace /path/to/trace.jsonl --output /new/run/output \
  --workers 12 --mode tfs --router-mode kv --admission-placement scheduler \
  --waiting-score-factor 0.1 --routing-python-path /new/build/output/python
```

启动器核对build receipt、基础提交和native binary SHA，仅对frontend设置overlay PYTHONPATH。
worker保持原环境。运行保存routing.build.json、routing.score.identity.json、routing.score.final.json、
routing.launch.json。WAITING_SCORE日志记录实际折扣候选分数。

构建脚本缺省dev构建用于功能检查；性能对比应使用`--release`，两臂使用同一binary。
只传`--routing-python-path`、不启用routing_accounting，可在同一构建下运行原完整计分基线。
启动器还核对overlay脚本和评分模块SHA，拒绝使用与当前代码不一致的旧构建。

## 6. 验证入口

```bash
PYTHONHASHSEED=0 python scripts/validate_routing_accounting.py \
  --output /new/smoke/output --routing-python-path /new/build/output/python --factor 0.1
python scripts/check_routing_accounting.py /new/smoke/output/run
```

测试覆盖配置边界、拒绝不激活、获准与回滚、无命中转换、未知RPC结果停止执行，
以及原生重复/过期permit、AttemptId和epoch。验收数字只在真实运行后写入VALIDATION。
两实例功能冒烟不能证明十二实例收益；当前不声称已完成取消/抢占或远程通信压力测试。

还验证了全轻请求、零heavy登记的运行。短请求可能在资源指标两次采样之间完成；新模式的验收
仍要求原生不等成本决策、最低分选择和最终清零，但不强制每次采样都捕获正峰值。旧模式的默认验收保持原规则。


## 7. block16 与 macOS 构建补充（2026-10-27）

等待账本继续记录完整 prompt token 数。原生评分器的输入是 block 数，因此等待折扣统一为
`(1 - waiting_factor) * waiting_prompt_tokens / block_size`。不对该值取整，
与原生 raw_prefill_tokens / block_size 一致。decode 成本仍保留原生 block 计数规则，
其块边界余量没有被改写；资源 booking 和真实 KV 块分配均不打折。
block1 的公式保持不变；配置只接受已覆盖的 1、16，其他块大小仍拒绝。
修改评分 overlay 后必须重新构建，旧 binary 的 receipt 不能用于新实现。

macOS 使用原生构建产物 lib_core.dylib，Python 模块目标仍为 _core.abi3.so。
构建不覆盖已安装 wheel。实验两臂应使用同一个 release 构建，旧 TFS 关闭评分折扣，
新 TFS 启用 α=0.1；避免将不同 native 构建的差异归因于准入策略。
实测与测试状态见 VALIDATION.md，不以本节表示验收已通过。

macOS 的 PyO3 扩展链接需对最终 cdylib 使用 `-undefined dynamic_lookup`，
由导入该扩展的 Python 解释器提供 Python 符号。构建器仅对最终扩展传入该参数，
不修改上游源码或全局依赖的 Rust 编译选项。具体编译器版本保存在 build receipt。
