# 真机 TFS 行为同步（2026-11-16）

此文记录 11-16 的 Dynamo 1.5 适配阶段。当前服务器 1.2 入口与启动方式见 [三实例说明](服务器三实例仿真.md)。

| 真机改动 | 仿真实现 |
| --- | --- |
| Dynamo 直接入口和分级索引 | 使用固定 Dynamo 1.5.0 的独立覆盖构建。一次共享存储画像在 picker 前生成。支持 fastokens。 |
| 重读评分 | heavy 等待时只折扣评分。设备 booking 仍记录完整负载。额度激活与回滚异步发送。超过三秒没有心跳，评分回到完整负载。 |
| Central 元数据入口 | 移除当前模式的 completions 和 models 代理路由。认证、UUID、epoch、共享单调钟、回报序列都要校验。 |
| 请求级降级 | 首文本和完成从 Dynamo 后台回报。执行状态不确定时立即释放当前请求记账。许可到期回收，迟到申请不能恢复额度。 |
| vLLM / Ascend | 获准之后才查询外部 KV。分配失败回滚。真实 KV 命中量可以与画像不同。支持 Ascend wrapper 禁用 balance 时的父类路径。 |
| MiniMax 估时 | 使用 TP2、batch=1、16 层的 50k v2 拟合。画像记录时间、来源和模型 SHA256。 |

Dynamo 的控制流和 vLLM 决策代码在 CPU 上真实运行。缓存块发布、传输、NPU 计算和 TP 一致性仍属于仿真边界。真机 ZMQ linger、RDMA、物理 OD 故障及模型 forward 无法在本模式验证。长 H/U 使用拟合公式外推，输出会标注。

历史网关模式保留原配置。运行命令见 [包内 README](../dynamo_vllm_cpu_sim/README.md)，验证见 [VALIDATION](../dynamo_vllm_cpu_sim/VALIDATION.md)。换机后需要按本地 Python ABI 重新构建 Dynamo overlay。仿真结果目录和已构建的 Rust 二进制属于本机产物。
