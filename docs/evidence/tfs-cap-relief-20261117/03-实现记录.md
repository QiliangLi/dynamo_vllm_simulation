## 关键实现语义

### cap_policy

- `legacy`（缺省）：`cap = max(1, floor(B_ref / θ))`，与改动前逐值一致。
- `measured`：已完成重读样本数 ≥ `cap_measured_min_samples`（默认 12）时，
  `cap = max(1, floor(B_ref / median(rate_i)))`；
  `rate_i = estimated_read_bytes / (first_token_s − reserved_s)`；
  样本不足回退 legacy（cap_basis=measured_fallback_theta）。
- `fixed`：`cap = cap_fixed_int`，跳过动态计算。

分类线 θ 仍按 legacy 口径更新，cap_policy 只改 cap 分母。

### 采样条件（sim/admission.py on_event first_token）

- `cap_policy == "measured"` 且 `lease_open`（该额度由本请求持有，完整栈仅重读开额）
  且 `is_heavy(profile)`（完整栈走冻结 hint）且 `occurred_s > reserved_s`
  且 `estimated_read_bytes > 0`。窗口为零或负不采样，除零保护 `max(median, 1.0)`。

### 弹性超发（read_admission.acquire）

- 判满时若 `overdraft_wait_s > 0` 且 `now − arrival ≥ overdraft_wait_s`
  且 `held < cap + overdraft_max_extra`：超额发放，日志 `read_permit_overdraft`
  （含 waited_s），permit 字段 `overdraft=True`，admission_reserved 的
  reason=overdraft。默认 `overdraft_wait_s=0` 完全关闭，行为与旧代码一致。

### BENCH_TFS_JSON

`BENCH_TFS_JSON='{"cap_policy":"measured"}'` 之类 JSON 覆盖 admission 键，
在 arm_config 内、normalize 之前生效；audit_queue_policy 重放时同环境变量
仍在，配置一致性断言不受影响。
