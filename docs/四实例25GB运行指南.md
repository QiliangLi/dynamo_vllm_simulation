# 四实例、六盘共享 25 GB/s 的仿真运行指南

在 Linux 或 WSL 的仓库根目录执行。入口为 `bash scripts/run_4w25.sh 负载 策略 新输出目录`。每次从冻结文件恢复完整 token、命中前缀和到达时刻，再启动 Dynamo 1.2 和四个 CPU vLLM 调度实例。四个实例合计共享 25 GB/s，每盘约 4.167 GB/s。MiniMax 16 层、TP=2 等效计算模型，每实例每步最多一条，单输出 token。

## 选负载

| 参数 | 冻结输入 | 请求 / 到达窗口 | A/B/C 条数 | 特点 |
|---|---|---|---|---|
| `408` | [ABC408](../benchmark/synthetic_abchalfb_408_8s_4_25GBps/README.md) | 408 / 8 s | 120/144/144 | A 命中 20,480、新算 2,048，B 的读取减半 |
| `540` | [ABC540](../benchmark/synthetic_abclonghit_540_12s_4_25GBps/README.md) | 540 / 12 s | 60/240/240 | A 命中 51,200、新算 768，B 命中 2,048、新算 4,096，C 零读 |
| `mooncake` | [Mooncake 87.5%](../benchmark/mooncake_head875_360_12s_4_25GBps/README.md) | 360 / 12 s | 240/90/30 | 开头 360 条，按总输入 token 计算约 87.5% 命中 |
| `agentx-narrow` | [AgentX 窄区间](../benchmark/agentx_narrow_358_12s_4_25GBps/README.md) | 358 / 12 s | 120/150/88 | A 需求 18.04–19.44 GB/s |
| `agentx-flex` | [AgentX 宽区间](../benchmark/agentx_flex_358_12s_4_25GBps/README.md) | 358 / 12 s | 120/150/88 | A 目标 15–20、B 3–8、C 0–3 GB/s |

AgentX 两版保留相同请求、总长度和到达时刻，改变各请求的命中和未命中 token。两版报告均可离线查看。[窄区间报告](../report/agentx_narrow_358_12s_4_25GBps/README.md) · [宽区间报告](../report/agentx_flex_358_12s_4_25GBps/README.md)

## 首次准备环境

按[环境与构建说明](服务器三实例仿真.md)完成 CPU vLLM 的 bootstrap、Ascend 调度补丁及仓库内 Dynamo 1.2 的独立构建和 NIXL 安装。已有同版本环境时复用即可。回到仓库根目录，指定解释器和 Dynamo 构建目录。

```bash
export DV_PYTHON="$PWD/dynamo_vllm_cpu_sim/.venv/bin/python"
export DYNAMO_PYTHON_DIR="$HOME/.cache/dynamo-server-sim/build-1.2/python"
# 已另行安装 upstream 源码时才需要指定 DV_UPSTREAM，默认使用包内 upstream。
RESULTS=$(mktemp -d "$HOME/four-worker-25gb.XXXXXX")
```

## 对比默认策略与普通 TFS

选一个负载，顺序运行两条命令。各轮各自启动服务并使用独立输出目录。顺序运行可避免共用本机端口。下例测宽区间 AgentX，把 CASE 换成上表任一参数即可测其他输入。

```bash
CASE=agentx-flex
bash scripts/run_4w25.sh "$CASE" light "$RESULTS/$CASE-light"
bash scripts/run_4w25.sh "$CASE" tfs   "$RESULTS/$CASE-tfs"
```

`light` 强制全部请求为轻读，保留实际 KV 读取及同一套路由。`tfs` 使用普通动态 P75 分类和额度，排队重读评分系数 α=0.1。两组均使用 FCFS，不启用空闲时超额放行。

## ABC540 和 AgentX 的固定额度对照

`a_cap1` 将输入标签 A 标为重读、B/C 标为轻读，全局仅有一个重读许可，首 token 时释放。ABC540 应有 60 条重读，两种 AgentX 各有 120 条。与上述同名负载的 light、tfs 比较。

```bash
for CASE in 540 agentx-narrow agentx-flex; do
  bash scripts/run_4w25.sh "$CASE" a_cap1 "$RESULTS/$CASE-a_cap1"
done
```

## 看结果

每轮会打印并保存 `summary.json`。例如 `cat "$RESULTS/agentx-flex-a_cap1/summary.json"`。其中 `makespan_s` 从首条客户端首次实发到最后一个响应结束。`worker_finish_s` 依实际执行日志将请求归到 worker 0–3，再取每个 worker 最后一个响应的结束时刻。四项共用同一客户端零点，`mean_worker_finish_s` 对四项等权平均。`mean_ttft_s` 和 `p95_ttft_s` 衡量每条请求从实发到首 token 的等待。

`input/manifest.json` 保存 trace 哈希，`run/report.json` 保存逐请求结果，`run/worker*.steps.jsonl` 保存逐层计算轨迹。`check.json`、`layer_check.json` 和 `read_admission.check.json` 均在 `run/`。入口核对完成数、读取字节、重读标记以及固定额度的实际峰值。失败时看本轮 `run.log`。

这些命令运行 CPU 仿真。真机上的 HTTP prepare 和 replay 使用单独的服务器工具及种子格式。
